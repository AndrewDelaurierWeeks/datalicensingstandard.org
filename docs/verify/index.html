Download the five files into one folder:

curl -O https://datalicensingstandard.org/TDLS-AI-v0.1.pdf
curl -O https://datalicensingstandard.org/TDLS-AI-v0.1.md
curl -O https://datalicensingstandard.org/TDLS-AI-v0.1.sha256
curl -O https://datalicensingstandard.org/TDLS-AI-v0.1.tsr
curl -O https://datalicensingstandard.org/TDLS-AI-v0.1.md.tsr

Check both files against TDLS-AI-v0.1.sha256:

sha256sum -c TDLS-AI-v0.1.sha256

It prints TDLS-AI-v0.1.pdf: OK and TDLS-AI-v0.1.md: OK.

Verify each token against its file. The root certificate is the self-signed DigiCert Trusted Root G4, SHA-256 fingerprint 55:2F:7B:DC:F1:A7:AF:9E:6C:E6:72:01:7F:4F:12:AB:F7:72:40:C7:8E:76:1A:C2:03:D1:D9:D2:0A:C8:99:88. On Debian and Ubuntu the system store holds it at the path shown:

openssl ts -verify -data TDLS-AI-v0.1.pdf -in TDLS-AI-v0.1.tsr -CAfile /etc/ssl/certs/DigiCert_Trusted_Root_G4.pem
openssl ts -verify -data TDLS-AI-v0.1.md -in TDLS-AI-v0.1.md.tsr -CAfile /etc/ssl/certs/DigiCert_Trusted_Root_G4.pem

Each command prints Verification: OK, after a line on standard error that names OpenSSL's configuration file. On another system, use a PEM file of this root certificate in place of that path; the venue's README says how to check its fingerprint and how to read each token's time.
